Initializing Express and Setting Up the App JavaScript const express = require('express'); const app = express(); const: A JavaScript keyword used to declare a constant variable (a variable whose value cannot be reassigned later). express: A variable holding the Express.js library package, which we imported using require(). Express is a framework that makes building web servers in Node.js simple. app: An instance of an Express application. Think of app as the central engine of your server—it listens for incoming traffic, handles routing, and sends responses back to users. 2. Configuring Middleware JavaScript app.use(express.json()); app.use(express.urlencoded({ extended: true })); app.use(express.static(path.join(__dirname, 'public'))); app.use(): A method used to mount middleware. Middleware functions are routines that run automatically on every incoming request before it reaches your custom endpoints. express.json(): A built-in Express middleware that takes raw JSON data sent from the front-end and parses it into a JavaScript object (req.body) so your server can easily read it. express.urlencoded({ extended: true }): Parses incoming data sent from HTML forms (multipart/form-data or URL-encoded form submissions). express.static(...): Tells Express to serve static files (HTML, CSS, client-side JavaScript, images) directly from a folder (public) so your browser can load them when visiting the site. 3. Handling User Sessions JavaScript app.use(session({ secret: 'super-secret-property-portal-key', resave: false, saveUninitialized: false, cookie: { secure: false } })); session(): Middleware from the express-session package. It creates a temporary session stored on the server side and issues a session cookie to the user's browser. secret: A private encryption key used to securely sign and encrypt the session ID cookie so users cannot tamper with it. resave: false: Tells the server not to save the session back to the store if nothing inside the session changed during the request. saveUninitialized: false: Prevents saving empty or uninitialized sessions (helps with login security and storage efficiency). 4. Comprehensive Code Walkthrough & Line-by-Line BreakdownBefore integrating the code, let's break down the new methods, variables, and architectural concepts step by step: A. MongoDB Atomic Increment ($inc) Code: await Property.findByIdAndUpdate(id, { $inc: { views: 1 } }) What is $inc? It is a native MongoDB update operator. Why use it? Instead of reading the document into memory, incrementing the number in JavaScript (property.views = property.views + 1), and saving it back (which causes race conditions if two customers view the page at the exact same split second), $inc instructs the database engine directly to increment the integer atomically on the disk. B. MongoDB Timestamps & Sorting Code: { timestamps: true } and .sort({ createdAt: -1 }) What does timestamps: true do? When added to a Mongoose Schema, it automatically injects and maintains two fields: createdAt (the date/time the entry was created) and updatedAt. What does .sort({ createdAt: -1 }) do? It orders the returned query array in descending order (-1), meaning the newest user registrations or newest customer search queries appear at the very top of your analytics table. C. Separation of View (Impression) vs. Click (Engagement) View / Impression: Counted automatically whenever a property card is rendered onto a user's screen. Click / Lead Engagement: Counted when a customer actually clicks on a listing card to open its detail view, inspect all photos, or watch the video tour. This ratio gives you your Click-Through Rate (CTR): //$$\text{CTR} = \left(\frac{\text{Clicks}}{\text{Views}}\right) \times 100$$
